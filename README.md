## 简报关键约束（做设计前反复确认）
1. 不能增加 capacity（不能靠“多招人/多买设备”解决）。
2. 单纯的“分散注意力”不算设计回应——要改变等待的**情境**：谁等、按什么顺序、有什么信息、什么预期、什么条件。
3. 至少识别 **两个 stakeholder 群体**——等待不会消失，只会转移，要能为“转移到哪”辩护。
4. 原型必须能让**陌生人在 5 分钟内**在 mid-semester fair 上测试。
